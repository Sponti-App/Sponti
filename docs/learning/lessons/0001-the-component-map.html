Lesson 1 · Orientation

The component map

Your win: by the end you can take any of Sponti's ~30 components and drop it into one of 6 layers — and know what that layer is allowed to do.

Sponti's whole UI lives in spa/components/. Thirty files in one flat folder looks like a pile. It isn't — there's a hidden hierarchy. The trick to reading any React app fast is to stop seeing files and start seeing layers.

The spine: how a page gets wrapped

Every page is wrapped by a stack of providers and one shell, defined once in app/layout.tsx. This is the skeleton everything else hangs on:

ThemeProvider — light / dark AuthProvider — who am I, am I logged in AuthGate — redirect if not authed ActionFeedbackProvider — "flare created ✓" toasts NewEventDrawerProvider — the global create-flare drawer AuthenticatedAppShell — bottom nav + notifications { page } — the actual screen

Read it top-to-bottom as "things that must be true before the page renders." Theme, then identity, then the gate, then app-wide UI affordances, then the page itself.

The 6 layers

  1. ProvidersCross-cutting context. The four above. If state must be readable from anywhere, it lives here.
  2. Shell / chromeThe frame around every page — authenticated-app-shell, bottom-nav, notifications-popover, the menu, auth frames. Rendered once.
  3. ViewsThe two home surfaces of a flare: map-view (now) and calendar-view (upcoming). Same object, filtered by timing.
  4. Event (flare) domainCreate/view/manage a flare: new-event-drawer, event-detail-sheet, host card, avatar stack, cancel/recurring modals.
  5. Identity & socialPeople and sharing: avatars, menu-profile, circle-stack-icon, qr-share-sheet, google-auth-button.
  6. UI primitivescomponents/ui/* — shadcn + Radix atoms (button, input, tabs, drawer…). Dumb, reusable, no business logic.

The one rule that explains the shape

Why is the bottom nav in the shell and not on each page? Because the notification badge is app-level state. A real decision was made and written down:

Authenticated app chrome is owned by AuthenticatedAppShell. BottomNav, the unread badge, and NotificationsPopover are rendered once at the shell level instead of by individual pages. — docs/decisions/app-shell-owns-bottom-nav.md

The shell even knows which routes should hide the chrome — hidesAuthenticatedChrome() strips it on auth pages, /event/new, and /qr/*. That's your first wiring instinct: chrome is a shell concern, never a page concern.

Retrieval practice

Don't scroll up. Pull it from memory — that's what makes it stick.

1. A new event-detail-sheet needs a styled toggle. Which layer should the toggle itself come from?

2. Where is the bottom navigation bar rendered for every page?

3. The map view and calendar view mostly show the same underlying thing. What is it?
