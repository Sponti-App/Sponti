Lesson 2 · One component, end to end

Tracing a join

Your win: follow a real user action — joining a flare — through all four layers, and see why event-detail-sheet contains zero business logic. This is the template for reading any action in the app.

In Lesson 1 you placed components into layers. Now we pick one flare-domain component — event-detail-sheet.tsx, the sheet that slides up when you tap a flare on the map — and watch a tap travel all the way to the database.

1 · The sheet is "dumb" on purpose

Open the file and look at its Props. Notice what it doesn't do: it never calls an API. Everything it can do is handed in from the parent as a callback:

PropDirectionMeaning
event, joined, isHostdata in ↓what to show
onJoin(event, eta)event out ↑"the user wants to join"
onLeave(event)event out ↑"the user backed out"
onSeeRoute / onCloseevent out ↑navigation intents

The only state it owns is UI state: selectedEta (which chip is lit) and a mirror of the event so the drawer can animate closed gracefully. That's the Lesson 1 rule made concrete: logic flows down, events flow up. The sheet renders and reports; it doesn't decide.

2 · The only "logic" it has is which button to show

One genuinely clever part is the CTA — a 4-way branch on the props, nothing more:

  • isHost → "edit flare"
  • joined → "see route" (if imminent) + "can't make it / leave"
  • imminent && !joined → ETA chips, button disabled until you pick one
  • else → "I'm in · {time}"

The ETA chips ("5 min … 1 hr") are the Sponti differentiator: joining an imminent flare isn't just a yes — it tells the host when you'll arrive. Hold that thought; it's the payload in step 3.

3 · The trace: tap → database

You tap "on the way · 15 min". Here's the whole journey:

domainevent-detail-sheet.tsx — onClick calls onJoin(event, "15 min")
↓  (event flows up to the parent)
pageapp/page.tsx — handleJoin turns "15 min" into an ISO time via etaToIso()
↓
lib/apievents.ts — updateMyRsvp(id, { rsvpStatus: "going", memberWillArriveAt })
↓  apiFetch PATCH
backendapi — PATCH /events/:id/me → controller → service → EventMember

Four layers, one clean line. The component knew none of this — it only knew to shout onJoin. That separation is why you can restyle the sheet without fear of breaking the join, and rewire the join without touching the sheet.

4 · A wiring observation for your mission

There are two places a user can join: this map sheet (driven by app/page.tsx) and the full route /event/[id]. Good news — both funnel into the same updateMyRsvp. No duplicate join logic to drift apart.

Gap-spotting instinct: when you find two UI surfaces for one action, the first question is "do they share the API call, or did someone copy-paste it?" Here they share it. That's the healthy pattern — note it, move on.
